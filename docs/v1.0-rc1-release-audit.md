- Files are sorted alphabetically: `tar --sort=name`.
- File modification times are clamped to an explicit release timestamp: `--mtime='2026-10-27 00:00:00Z'`.
- User and group ownership IDs are normalized: `--owner=0 --group=0 --numeric-owner`.
- Gzip timestamp headers are suppressed: `gzip -n`.

## 6. Benchmark Claim Audit & Performance Boundaries

Review of [`benchmarks/results/milestone-25-release-audit.json`](file:///benchmarks/results/milestone-25-release-audit.json) and [`docs/benchmark-methodology.md`](file:///docs/benchmark-methodology.md):

1. **Compilation Speed**:
   - Vanta compiles in **~0.24s** vs `rustc` with LLVM in **~1.85s** (**7.7x faster**).
   - *Technical Basis*: Vanta uses a single-pass handwritten recursive-descent parser, focused MIR SSA passes, a fast graph-coloring allocator, and direct x86-64 machine code emission, using GCC only as an ELF linker.
2. **Binary Footprint**:
   - Vanta binaries are **~22.5 KB** vs Rust at **11.8 MB** (**524x smaller**).
   - *Clarification*: Vanta binaries dynamically link `libc.so.6` and statically link lightweight runtime glue (`libvanta_rt.a`). Rust release binaries statically embed the unstripped Rust standard library (`libstd`) with panicking, unwinding tables, and backtrace metadata. Stripping Rust binaries would reduce their footprint significantly (~300 KB to 1 MB).
3. **SIMD & Vectorization Limitation**:
   - In tight loops where GCC and Rust leverage 256-bit AVX2 vector instructions (e.g., `lsr_workload`), GCC and Rust outperform Vanta by $5\times\text{--}8\times$. Vanta v1.0-RC1 emits scalar 64-bit integer operations and does not yet feature an auto-vectorizer.
4. **Generalization Notice**:
   - Vanta makes **no generalized claim** of being faster than Rust or C. Measured performance gains apply specifically to the tested 18 workloads under documented configurations.
